# Learn about AI analysis in Data Security Investigations | Microsoft Learn

Important

Data Security Investigations uses generative artificial intelligence (AI), large language models, and orchestration in the analysis of data in your organization. Results generated by AI might not always be accurate or complete. While we strive to provide reliable and helpful information, AI systems can produce incorrect or false results. It is important to verify the information and use it with caution. Microsoft makes no warranties, express, implied, or statutory, as to the information provided by AI systems.

Data Security Investigations uses AI services and tools to help you quickly review and take action on items associated with security incidents. AI-related services include the following tools:

- Vector search
- Categorization
- Examination

## Vector search

Vector search in Data Security Investigations provides a way to contextually search through data that you add to the investigation scope by using advanced orchestration and embeddings. Vector search is a search engine technology that focuses on understanding the meaning and context behind words and phrases in a query, rather than just matching keywords.

Some key aspects of vector search are:

- **Contextual understanding**: Vector search interprets the context of your search terms, considering factors like your organization, search history, and the overall meaning of the query.
- **Intent recognition**: Vector search works to understand your intent, whether you're looking for information, trying to take an action, or seeking a specific type of content associated with a search.
- **Relevance and accuracy**: By focusing on the semantics (the meaning and intent of words in your query), vector search provides more accurate and relevant results and improves the overall search experience.
- **Suggested search (preview)**: Vector search also enables customized suggested search queries for you to select based on the [investigation context](data-security-investigations-investigation#ai-context-for-investigations) or any previous [searches](data-security-investigations-search) in an investigation. If your investigation doesn't have a context defined and you don't have any previous searches, you can choose from the following default suggested searches:

    - Look for anything containing credentials or passwords
    - Find all content containing sensitive information
    - List all legal and financial documents

When investigators in your organization investigate compromised data sets, vector search in Data Security Investigations can significantly enhance your investigation by addressing several key challenges:

- **Identifying relevant information**: Vector search understands the context and intent behind your queries. This focus helps you quickly locate relevant documents, emails, or records, even if they don't contain the exact keywords you used.
- **Handling ambiguity**: Vector search disambiguates terms that have multiple meanings, ensuring that you get results that are contextually appropriate to your investigation.
- **Reducing noise**: Vector search filters out irrelevant information, so you can focus on the most pertinent data and reduce the time spent sifting through unrelated results.
- **Improving efficiency**: Vector search streamlines the search process, making your investigation more efficient and effective by quickly surfacing the most relevant information.

### How it works

When you create an investigation and define the scope, the system automatically prepares data for AI. Starting June 2026, add to scope automatically encompasses the previous **Prepare for AI** action for all new investigations. You can then run vector searches over the data set. While previous steps of the process allow for simple keyword, metadata, and date range search, vector search uses AI embeddings to contextually search through data. This process allows investigators to find items without knowing their exact content.

Important

Items are vectorized if they contain text or [supported image content](data-security-investigations-ref-supported-file-types#image) with extractable text. For JPEG, PNG, and scanned PDF files, Optical Character Recognition (OCR) automatically extracts text from images before vectorization. Meeting invites and calendar notifications without text in the body are excluded from vectorization.

Vector search works by first running all scoped data in an investigation through an AI embeddings model. This model extracts semantic meaning from every item in your data set and breaks them into smaller parts. This process is called embedding and allows Data Security Investigations to use dimension values to understand your data contextually. A semantic search index is built from these values that you can query.

When you create a vector search query in an investigation, AI automatically expands and broadens your query and runs the query through the semantic search index. Data Security Investigations then matches the semantic meaning of your query with the semantic meaning of your content and returns all contextually relevant items.

For example, if you search for "Confidential data included in the Contoso Security project", the vector search engine understands that you're looking for confidential data in this specific project rather than simply matching keywords (*confidential*, *data*, *Contoso*, etc.) contained in the search query. Using vector search, you can query impacted data to find all data items related to a particular subject, even if keywords are missing.

Additionally, a search relevance score is automatically assigned to each item returned. The search relevance score helps you quickly determine the confidence level of the connection between your search and the items identified by vector search.

For more information about vector search concepts, see the concepts section in the [Vectors in Azure AI Search](/en-us/azure/search/vector-search-overview#vector-search-concepts) article.

## Search with AI (preview)

Building on vector search, [Search with AI (preview)](data-security-investigations-ai-analysis#use-search-with-ai-preview) incorporates retrieval-augmented generation (RAG) capabilities and optimizes the search results model. This feature includes search relevant items based on item file types, sizes, versions, and more.

This capability expansion to vector search also includes a search summary based on individual items returned in the search, including citation links to specific search results samples, to help you quickly evaluate if the search meets your needs.

## Categorization

When your organization is breached and you identify the impacted data, investigators need to prioritize data to start identifying security risks. Data Security Investigations categorization speeds up investigations by automatically grouping content around the data security risks you care about, so analysts can narrow thousands of files down to a small set of prioritized, meaningful clusters - without manual review.

You can [use **Standard** or **Advanced** AI-powered categorization](data-security-investigations-ai-analysis#use-categorization) in Data Security Investigations to more quickly reason through and prioritize potentially impacted data. To categorize data, you can select all or some default category options, use AI-suggested categories based on their investigation, or create your own custom categories.

You can also [add categories incrementally](data-security-investigations-ai-analysis#add-or-update-categories) after an initial categorization run completes. When you add new categories, only the net new categories are processed and previously categorized data is preserved. You can also change existing categories between **Standard** and **Advanced** processing levels.

The AI-generated categories are enriched with additional information for subject-level content in scope:

- **Name**: The name of the category or area based on the content
- **Summary**: A short description of the underlying content

Within each category, you can use vector search and examination tools on any content.

### How categorization processes data

Categorization is designed to prioritize the most relevant content for each selected category rather than analyze every item in the investigation scope. When you run categorization, the system uses AI to evaluate content against your selected categories, scores each content segment for relevance, and retains the highest-confidence results. Content that doesn't meet the relevance threshold for a category isn't included in the results for that category.

Because categorization is optimized for speed and cost efficiency, be aware of the following considerations:

- **Results represent prioritized content**: Categorization surfaces a prioritized subset of the most relevant content for each category, not an exhaustive analysis of all items in your data set.
- **Content volume can affect results**: In large datasets, documents with extensive content might be more strongly represented in results. Some relevant items might not appear if they score below the relevance threshold.
- **Categories are processed independently**: Each selected category is evaluated separately. The number of categories you select affects processing time and compute unit costs but doesn't change how relevance is determined for individual categories.

When you select **Standard** categorization, the system groups content into your selected categories based on relevance scoring. When you select **Advanced** categorization, the system performs additional processing to identify and organize content into specific topics within each category, providing more granular groupings for deeper analysis.

Tip

If your investigation requires comprehensive analysis of all content in scope, use [examination tools](data-security-investigations-ai-analysis#use-examination-tools) instead of or in addition to categorization. Categorization is best for fast prioritization and triage of large datasets, while examination provides targeted, item-level analysis for selected items.

### Default categories

Data Security Investigations includes default categories to categorize items in your investigation scope. When you run categorization, you can select all default categories or only the default categories that apply to the scope of your review. The analysis ignores unselected default categories, and you can't review results for these categories.

AI processing determines the initial default categories for content items:

- **Business information**: General business information. This category typically contains a large number of items. Some example areas in this category might include digital engagement and analysis, user and human resources, routine administrative communication, customer engagement/experience, and more.
- **Communication records**: General communication information. This category also typically contains a large number of items. Use this category to see your investigations based on areas of communications. Some example areas in this category might include client complaints, holiday greetings, internal memos, project updates, and more.
- **Credentials and access information**: Information related to access assets in investigations. This information helps identify potentially risky data and communications in your organization. Some example areas in this category might include user credentials, unauthorized database access, data exposure, and more.
- **Customer information**: Information shared with customers. Use this category to understand what customer data might be at risk. Some example areas in this category might include payment confirmations, customer experience improvement, delivery information, and more.
- **User information**: Information related to users in your organization. This category also typically contains a large number of items. Some example areas in this category might include user employment information, user retention strategies, specialized group memberships, and more.
- **Financial information**: Financial information in an investigation. Some example areas in this category might include financial planning, grant opportunities, budgets, financial statements, and more.
- **Health information**: Health and medical-related items in an investigation. Some example areas in this category might include wellness and health records, COVID-19 safety protocol updates, health claims and incident reports, and more.
- **Incident and investigation information**: Items about incidents and investigations in an investigation. This category includes security incidents and investigations within your organization. Some example areas in this category might include data breach, health records incidents, high-risk client account monitoring, and more.
- **Intellectual property**: Intellectual property (IP) data in an investigation. Some example areas in this category might include future patent applications, research and development work, experiment result metrics, and more.
- **Marketing information**: Marketing data in an investigation. Some example areas in this category might include press releases, advertising campaigns, marketing and sales plans, or strategies and more.
- **Operational information**: Your organization’s operational data. Some example areas in this category might include logistics, shipping, inventory, compliance, tax records, and more.
- **Personally identifiable information**: Group [personal data](data-security-investigations-personal-data) and related items in an investigation. Some example areas in this category might include event guest lists, staff and training sessions, employee personal information, and more.
- **Regulated data**: Regulated data in an investigation. Some example areas in this category might include regulatory, data protection, regulatory records, and more.

Note

Investigations auto-created by [proactive AI insights from Data Security Posture Management (DSPM)](data-security-investigations-investigation#enable-proactive-ai-insights-from-dspm) use five fixed risk categories: Credentials and access information, Personally identifiable information, Financial information, Confidential information, and Intellectual property. These categories are separate from the 13 default categories listed here and aren't configurable in the current preview.

### Suggested categories

Data Security Investigations also provides AI-generated suggested categories based on the content analyzed in your investigation scope. These suggested categories automatically help investigations review items grouped in unexpected or unknown areas. Depending on the type of content included, the suggested categories vary.

If the content analyzed primarily focuses on a specific subject area outside of the default category areas, the suggested categories customize to that specific content area. For example, if the analyzed content focuses on a highly confidential subject with terms and concepts specific solely to your organization, the suggested categories are automatically created for these areas. These categories are unique to your organization and the content analyzed.

### Custom categories

Data Security Investigations enables you to manually create [custom categories](data-security-investigations-ai-analysis#use-categorization) for the generative AI process to use when analyzing content. By defining categories that best fit your investigation needs, you can save time and let the AI process automatically categorize items based on these custom categories.

Custom categories can be specific words or phrases that capture the specific nature of content you're interested in during the investigation. For example, custom categories might include *Security vulnerability*, *Bug fix*, specific project code names, or custom intellectual property like R&D related to a specific medicine or drug candidates.

## Examination

As you identify items that require deeper analysis, Data Security Investigations provides AI-based examination capabilities to help you focus on key security and sensitive data risks.

- **Credentials**: Use this examination focus area to scan and extract credentials from all selected items in an investigation scope. This information provides investigators with a quick way to understand which accounts and credentials are associated with a security incident and that might be potentially exfiltrated.
- **Risk**: Use this examination focus area to score all the risk areas in selected files to help investigators focus and prioritize investigations. This tool provides the overall risk for each item, if the item is privileged content, and other specific risks for the item.

    Types of risk areas include:

    - Asset identifiers
    - Credentials and secrets
    - Evidence of threat actor and breach discussions
    - Urgent security incidents
    - Vulnerability and security hygiene
    - Personal and sensitive content
    - Network and access information
    - Policy compliance and data protection
    - Infrastructure information
    - Customer information
    - Government information
    - Privileged information
    - Trade secrets
- **Mitigation**: Use this examination focus area to score the risk for selected files and enable Data Security Investigations to provide you with mitigation instructions for what to do next. Selected files get a risk score, risk summary, and detailed mitigation recommendations to prevent more harm from a content breach.
- **Personal data**: Use this examination focus area to identify and extract [personal data](data-security-investigations-personal-data) from selected items in an investigation scope. This information provides investigators with a quick way to understand what personal data types are present in data associated with a security incident, including names, email addresses, employee IDs, IP addresses, and other PII.
- **Custom**: Use this examination focus area to define a custom analysis using a natural language prompt. Describe what you want the AI to look for in selected items, up to 2,000 characters. Custom examinations produce the same structured results as built-in focus areas, with findings validated by safety guardrails. For more information about creating custom examinations, see [Create a custom examination](data-security-investigations-ai-analysis#create-a-custom-examination).
